# Plan, validate and publish multi-surface network changes safely

**Priority:** P1. **Depends on:** drafts 02 (read model), 04 (resources), 07 (policy) and 09 (DNS). **Area:** coordinator transactions plus console.

## Gap and outcome

NetBird offers Control Center draft mode. BlakTail has etag-aware policy/DNS writes and one-step rollback, but no coherent way to preview a linked resource, route and policy change before activation. One-page client-side drafts must not claim atomicity across coordinator objects.

## Scope

- Design versioned, organisation-bound server-side draft containing proposed resource/route/policy/DNS changes. Define validation, actor ownership, expiry, revision preconditions and a single audited publish boundary; if atomic publish cannot be guaranteed, display exact partial-commit/rollback semantics before implementation.
- Preview diff and effective reachability for named test identities, nodes, ports and both IPv4/IPv6. Flag lockout of last owner, exposed default routes, route overlap, deletion impacts and DNS conflicts; require explicit confirmation for risky scope changes.
- Allow safe discard, rebase after etag conflict and rollback to known version without storing secrets in draft payloads. Members may view only authorised summaries, never publish. Do not make an offline browser cache source of truth.

## Acceptance / proof

Concurrent editors cannot overwrite one another; failed validation leaves live policy unchanged; publish records who/when/before-after revision. Integration test verifies resource and access are never temporarily broadly exposed, including coordinator restart, partial failure and cross-org attempts. Browser test verifies preview text matches activated policy. No claim of transactional safety before proof.

**Evidence:** `docs/policy.md`, `docs/org-dns.md`, `docs/admin-api.md`; https://docs.netbird.io/manage/control-center/draft-mode.

## Status (2 October 2026)

**Done:** `blaktail-coord/src/change_drafts.rs` with migration slot 22 (`change_drafts`, SQLite + Postgres). Organisation-bound, versioned drafts for access policy, DNS and the full network-resource set: create from live state, edit (draft-version precondition → 412), rebase, preview, publish, discard; 7-day expiry; at most 50 open drafts per organisation; credential-looking keys refused; members and auditors get summaries without payloads. Every action requires the permission of each surface the draft touches (`ManagePolicy`/`ManageDns`/`ManageNetworks`). Preview and publish share `apply_tx`: all surfaces run through the existing validators and writers on ONE database transaction (policy via `publish_acl_tx`; resources via the existing `create/update/delete_in_tx`, whose control-revision bump moved to their callers; DNS via `write_org_dns_tx`, split out of `publish_org_dns`). No surface had to be excluded. Publish bumps the control revision once, re-checks each surface's base etag inside the transaction (409 "rebase required"), refuses unconfirmed risk flags (409), and audits `change_draft.published` with the draft id and before/after revisions, plus `acl.updated`/`dns.updated`/per-resource entries and webhooks. Preview returns per-surface diffs, resource operations, reachability added/removed (topology edge diff), named source/destination/protocol/port verdicts before and after, risk flags (deny removed, defaults widened, default-route exposure, nested overlap, resource deleted, access widened/removed, DNS warnings), and notes that last-owner lockout cannot arise on these surfaces. Console `/changes` and `/changes/{id}`: list, create from live, JSON editing per surface, preview with diffs, publish with per-risk confirmation, rebase, discard; the organisation is pinned by a hidden field so switching organisation cannot retarget a mutation.
**Proven by tests:** `change_drafts::tests` — concurrent editors: stale draft version 412, second draft's publish 409 with live policy unchanged, double publish refused, rebase then publish succeeds; invalid DNS after valid policy and resource, and an invalid resource after valid policy, both leave every surface unpublished; the corrected draft publishes all three surfaces with one control-revision bump and an audited draft id; another organisation gets 404 on every draft route and an empty list; members and auditors cannot create, preview, rebase, discard or publish and never see payloads; expired drafts cannot publish; discarded drafts cannot be edited.
**Still needs live/field proof or a decision:** a PostgreSQL concurrency run (the org-row lock taken by the first control-revision bump serialises writers; proven on SQLite only here); coordinator restart mid-publish (atomicity relies on the database transaction and was not tested against a killed process); a browser test that preview text matches the activated policy; agents converge on their next poll, so "never temporarily broadly exposed" holds for coordinator state, not as a fleet-wide instant switch; multi-surface rollback to a known version (only the existing one-step policy/DNS rollback exists); device-approved routes and posture checks are not draft surfaces yet; reachability preview is address-family neutral rather than separate IPv4/IPv6.

### Live lab: PostgreSQL publish races (3 October 2026)

- **Proven live:** `deploy/homelab/prove-pg-races.sh` runs two coordinator replicas on one PostgreSQL 16 database and releases 8 concurrent HTTP writers per round across both replicas, 50 rounds per race. Same draft version published 8 times: exactly one 200 per round, 350 × 409, policy revision +1 per round. Eight rival drafts based on the same policy published at once: exactly one 200 per round, 350 × 409 "rebase required", losers stay open, stored policy always the winner's. 0 lost updates in 100 rounds. Not covered: a coordinator killed mid-publish.
